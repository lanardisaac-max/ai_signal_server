# Mandatory LTI portfolio handoff accounting

## Mandatory LTI development-accounting doctrine — October 30, 2026

Before every development/execution/coding/implementation handoff and after each
returned checkpoint, read [the portfolio doctrine](https://github.com/lanardisaac-max/owner-command-center/blob/main/docs/governance/LTI-DEVELOPMENT-DOCTRINE.md) and the current
business ledger. Reconcile all discovered repositories and relevant working/release
branches against accepted work and future plans; use delta reads for unchanged proof.
Maintain 100% coverage of known required monetization scope with stable task IDs.
Report task-derived total, ✅ complete, ❌ incomplete, percentage, changes and as-of
time. Preserve prior acceptance. Missing evidence is not proof of missing work.
Run the canonical handoff validator; partial scope, stale snapshots, duplicate work
and false counts cannot be handed off as complete/current. New or unmapped businesses
remain covered and visible. This policy does not resume paused work, override resource
isolation, authorize new spend or waive protected-action/production approval.

Read AGENTS.md and LTI-DOCTRINE.json before work. Preserve existing project safeguards and accepted completion.
